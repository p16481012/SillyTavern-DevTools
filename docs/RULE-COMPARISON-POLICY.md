# Rule Inspector 비교 정책

비교 정책은 서로 대안인 프롬프트를 한 그룹으로 묶어 의미 없는 내부 충돌을 줄입니다. 정책은 현재 브라우저의 로컬 저장소에만 보관되며 SillyTavern 프롬프트, 캐릭터 카드, 프리셋을 수정하지 않습니다.

## 빠른 설정

예를 들어 다음 설정 프롬프트가 있다고 가정합니다.

- `출력언어 | 한국어`
- `출력언어 | 일본어`
- `출력언어 | 영어`

1. ST DevTools에서 **규칙 검사 → 비교 정책**을 엽니다.
2. 해석 방식은 `템플릿`을 선택합니다.
3. 이름 패턴에 `{group} | {option}`을 입력합니다.
4. 그룹 동작은 `대안 그룹`, 적용 대상은 `설정 프롬프트만`을 선택합니다.
5. **이름 규칙 추가**를 누른 뒤 미리보기에서 `출력언어 · 한국어`처럼 인식되는지 확인합니다.
6. **설정 적용**을 눌러 브라우저에 저장합니다.

이제 세 프롬프트에서 추출된 언어 지시 원자끼리는 충돌 관계를 만들지 않습니다. 그러나 그룹 밖의 다른 프롬프트가 특정 언어를 강제하면 여전히 비교하고 실제 원자 쌍·근거를 표시합니다.

## 이름 형식별 예

| 프롬프트 이름 | 해석 방식 | 이름 패턴 | 고정 그룹 |
|---|---|---|---|
| `출력언어 | 한국어` | 템플릿 | `{group} | {option}` | 비움 |
| `[출력언어] 한국어` | 템플릿 | `[{group}] {option}` | 비움 |
| `출력언어❤️한국어` | 템플릿 | `{group}❤️{option}` | 비움 |
| `custom L:한글` | 템플릿 | `custom L:{option}` | `출력언어` |
| `LANG::ko` | 정규식 | `^(?<group>[^:]+)::(?<option>.+)$` | 비움 |

템플릿의 나머지 문자는 일반 문자로 처리되므로 원하는 구분자를 사용할 수 있습니다. 고정 그룹이 없으면 `{group}`과 `{option}`이 각각 한 번 필요합니다. 고정 그룹을 쓰면 이름 패턴에는 `{option}`만 있어도 됩니다.

정규식에는 `group`과 `option` 이름 캡처를 사용하는 방식을 권장합니다. 패턴은 256자 이하만 허용하며 역참조·중첩 반복·반복 wildcard처럼 브라우저를 오래 멈출 위험이 큰 구조는 실행하지 않고 화면에 오류로 표시합니다. 이름 규칙은 템플릿이 더 읽기 쉽고 안전하므로 정규식은 템플릿으로 표현하기 어려운 형식에만 사용하세요.

## 그룹 동작

- `대안 그룹`: 같은 그룹 내부 비교를 제외합니다. 실제 요청에 서로 다른 옵션이 둘 이상 포함되면 그룹 경고 한 건을 표시합니다.
- `내부 무시`: 같은 그룹 내부 비교와 다중 활성 그룹 경고를 모두 숨깁니다. 그룹 밖 프롬프트와의 비교는 유지합니다.
- `일반 그룹`: 그룹 정보를 표시하지만 기존처럼 모든 비교를 수행합니다.

`내부 무시`도 소스 자체를 전체 Rule Inspector에서 제거하는 기능은 아닙니다. 컨텍스트 사용률, 단일 소스 크기, 명시적인 이전 지시 무시 문구처럼 쌍 비교가 아닌 검사는 계속 적용될 수 있습니다.

## 검사 범위

`*`는 지원하는 모든 소스 쌍 비교에 정책을 적용합니다. 일부 검사에만 적용하려면 다음 ID를 쉼표로 구분합니다.

- `language`: 응답 언어
- `format`: 출력 형식
- `role`: 역할 선언
- `directives`: 긍정·금지 지시
- `duplicates`: 여러 소스의 중복 문장

예를 들어 `language, format`은 같은 그룹의 언어와 형식 비교만 제외하고 역할이나 지시 비교는 유지합니다.

## 수동 지정

이름 규칙으로 구분하기 어려운 프롬프트는 현재 스냅샷의 목록에서 직접 선택해 그룹과 옵션을 입력할 수 있습니다.

- 가능한 경우 SillyTavern 설정 프롬프트의 안정적인 `identifier`로 연결합니다.
- 이름이 바뀌어도 같은 identifier가 유지되면 수동 지정도 유지됩니다.
- 수동 지정은 모든 이름 규칙보다 우선합니다.
- 같은 프롬프트를 다시 수동 지정하면 이전 지정을 대체합니다.

과거 스냅샷에 identifier가 없으면 이름 또는 소스 ID를 보조 식별자로 사용하므로 이름 변경 뒤 다시 지정해야 할 수 있습니다.

## 규칙 순서와 미리보기

이름 규칙은 화면 위에서부터 평가하며 처음 일치한 규칙만 적용합니다. `위로`와 `아래로` 버튼으로 우선순위를 바꿀 수 있습니다.

설정 전에는 미리보기에서 다음 항목을 확인하세요.

- 의도한 프롬프트만 같은 그룹으로 인식되는지
- 그룹과 옵션이 원하는 위치에서 분리되는지
- 설정상 활성과 실제 요청 포함 상태가 어떻게 표시되는지
- 수동 지정 또는 이름 규칙 중 어느 방식이 적용됐는지

분석 결과의 **제외된 비교**에는 두 소스, 검사 범주, 그룹과 제외 이유가 표시됩니다. 이 목록이 예상보다 넓으면 규칙의 적용 대상을 `설정 프롬프트만`으로 좁히거나 더 구체적인 이름 패턴을 사용하세요.

## 실제 요청 포함 상태

Rule Inspector는 설정 화면에서 활성화됐다는 사실과 실제 요청 payload에 포함됐다는 사실을 구분합니다.

- 비활성 설정 프롬프트는 비교하지 않습니다.
- 활성 상태여도 현재 요청에서 발견되지 않은 프롬프트는 비교하지 않습니다.
- 대화 기록, tool schema·호출·결과, 멀티모달 표시와 최종 합성 결과는 지시 소스끼리의 비교에서 제외합니다.
- 참고 데이터는 원자를 표시할 수 있지만 일반 지시와 자동 충돌 비교하지 않습니다.
- 설정 프롬프트와 연결되지 않은 실제 system/developer 요청 조각은 별도 요청 소스로 보존해 그룹 밖 비교에 포함합니다.

복잡한 매크로, 조건부 조립 또는 provider 변환 때문에 포함 상태를 확정하지 못할 수 있습니다. 미리보기와 소스 연결 근거를 함께 확인하세요.

## 현재 한계

비교 정책은 비교 대상을 구조화하는 기능이며 자연어 의미를 이해하는 AI 분석이 아닙니다. v0.9.0은 언어·형식·역할·일부 긍정/금지 지시를 원자로 분해하고 조건·예외를 보존하지만, 명시적인 정적 패턴을 중심으로 검사합니다.

다음 항목은 아직 완전하게 판단하지 못합니다.

- 같은 뜻을 다른 문장으로 쓴 의미 중복
- 여러 조건부 지시 사이의 논리적 포함·배타 관계와 예외 범위
- 말투·정체성·안전·메모리의 의미 충돌
- 실제 프롬프트 우선순위 승자
- 숨은 모순과 복합 추론

이 항목은 이후 정적 구조를 확장한 뒤 선택적 AI 분석으로 보완할 예정입니다.
