# v0.5.0 기술 구현 현황

- SillyTavern Chat Completion·Text Completion prompt/settings/generation 이벤트 캡처
- 활성 로어북·생성 유형·모델·sampler·출력 한도와 캡처 경계 기록
- credential 형태 필드의 재귀 마스킹과 순환 참조 보호
- 스키마 v2 및 v1 자동 마이그레이션
- 캐릭터·페르소나·작가 노트·로어북·확장 프롬프트·채팅 기록 소스 분해
- 정확히 일치한 원본 문자열의 비중첩 최종 범위를 소스당 최대 50개 기록
- 채팅별 IndexedDB 타임라인, 최근 100개 보관, 개별·전체 삭제
- 원본 소스↔최종 프롬프트 상호 탐색
- 토큰 성장·로어북 활성/제거·소스별 diff
- 컨텍스트·중복·언어·형식·역할·긍정/금지·우선순위 문구·대형 소스·미연결 소스 검사
- 규칙별 활성화 및 수치 임계값 설정
- 언어·형식·역할·긍정/금지·우선순위 문구 규칙의 관련 소스와 정확한 최종 근거 범위 이동
- 일반/정규식/대소문자 검색과 JSON·TXT·Markdown 내보내기
- API 경계 fixture, 동시 settings 예약, 100개 스냅샷과 범위 sweep 회귀 테스트

## 부분 구현 또는 알려진 경계

- provider 서버가 변환한 실제 최종 HTTP 본문은 공개 프런트엔드 이벤트 범위 밖입니다.
- settings-ready 연결은 프롬프트 유형별 순서와 동기 예약을 사용합니다. 공개 요청 ID가 없는 장시간 중첩 생성은 완전한 상관관계를 보장하지 않습니다.
- 같은 요청 객체가 여러 호환 이벤트에 전달되면 중복으로 간주합니다. 호스트가 별도 생성에도 동일 객체 인스턴스를 재사용하는 특수 경로에서는 request-ready 연결 대신 prompt-ready 대체 캡처가 사용될 수 있습니다.
- 소스 연결은 동일 문자열 기준입니다. 매크로·템플릿·정규식·공백 변환 결과는 `미확인`일 수 있습니다.
- Chat Completion의 role wrapper, tool/function call과 멀티모달 이미지·오디오 토큰은 전용 소스로 완전히 분해하지 않습니다.
- 마지막 assistant 메시지는 prefill 후보로 보수적으로 추정하므로 일반 마지막 응답과 구분하지 못할 수 있습니다.
- 로어북 비교는 활성화·제거·유지를 다루며 동일 UID 내부 내용 변경은 별도 상태로 표시하지 않습니다.
- 소스 diff는 내용·토큰·연결 상태를 비교합니다. role·depth·position·enabled만 바뀐 경우는 누락될 수 있습니다.
- 규칙 검사는 정규식 기반입니다. 자연어 의미, 조건부 예외, 실제 우선순위 승자를 확정하지 않습니다.
- 중복·대형 소스 규칙은 소스 전체 범위를 근거로 사용하며, 컨텍스트·미연결 규칙처럼 정확한 문자 범위가 없는 결과는 최종 프롬프트 카드로 이동합니다.
- 규칙 판정은 전체 최종 텍스트를 확인하지만 관련 소스 계산에서는 채팅 기록을 제외합니다. 검증용 충돌 지시는 시스템·캐릭터·확장 프롬프트에 두는 것이 정확합니다.
- 100개 타임라인 순수 함수와 저장 회귀는 자동화했지만 실제 IndexedDB와 SillyTavern 통합 E2E는 사용자 환경 검토가 필요합니다.
