# v0.8.1 사용자 실사용 체크리스트

v0.8.1은 v0.8.0 Rule Inspector 구조화를 유지하면서 밝은 테마와 좁은 패널의 UI 문제를 보완한 패치입니다. 자동 검사와 로컬 브라우저 샌드박스를 통과한 상태로 배포합니다.

## UI 패치 빠른 검토

- [ ] 확장 목록과 ST DevTools 제목에 `v0.8.1`이 표시된다.
- [ ] 탭을 차례로 눌렀을 때 선택한 탭 한 개에만 강조선이 남고 다른 탭에 검은 테두리가 생기지 않는다.
- [ ] 패널 폭을 약 420px로 줄여도 타임라인의 진단 버튼, 컨텍스트 내보내기 버튼, 규칙 검사의 관련 소스 버튼 글자가 세로로 쪼개지지 않는다.
- [ ] 밝은 테마에서 프롬프트 탐색기의 `정확`·`정규화 연결`·`템플릿 후보`·`미확인` 상태가 읽힌다.
- [ ] 밝은 테마에서 프롬프트 비교의 `추가`·`수정`과 타임라인의 이전 턴 토큰 변화가 선명하게 읽힌다.
- [ ] 검색 탭의 `정규식`과 `대소문자 구분` 체크박스가 같은 행에 놓인다.

## 가장 중요한 10분 검토

- [ ] 설정 프롬프트 세 개를 `출력언어 | 한국어`, `출력언어 | 일본어`, `출력언어 | 영어`처럼 만들고 실제 요청에 포함한다.
- [ ] 비교 정책이 없을 때 규칙 검사에 응답 언어 충돌이 표시된다.
- [ ] 비교 정책에서 템플릿 `{group} | {option}`을 추가하면 미리보기에 `출력언어 · 한국어/일본어/영어`로 인식된다.
- [ ] 정책 적용 뒤 세 언어 옵션끼리의 언어 충돌은 사라지고 `제외된 비교 3건`과 다중 활성 그룹 경고 한 건이 표시된다.
- [ ] 이름 규칙을 적용해도 출력언어 그룹 밖의 별도 언어 강제 프롬프트와는 계속 충돌한다.
- [ ] 비교 정책을 저장하고 SillyTavern을 새로고침해도 규칙이 유지된다.
- [ ] 기본값 복원 뒤 정책이 없어지고 원래 충돌 결과로 돌아온다.
- [ ] ST DevTools를 열고 정책을 바꿔도 실제 프롬프트·캐릭터 카드·프리셋이 수정되지 않는다.

세 옵션 중 실제 요청에 하나만 포함됐다면 충돌과 다중 활성 경고가 없는 것이 정상입니다. 먼저 미리보기의 `실제 요청에 포함` 상태를 확인하세요.

## 이름 규칙 형식

- [ ] `출력언어 | 한국어`와 `{group} | {option}` 조합이 인식된다.
- [ ] `[출력언어] 한국어`와 `[{group}] {option}` 조합이 인식된다.
- [ ] `출력언어❤️한국어`와 `{group}❤️{option}` 조합이 인식된다.
- [ ] `custom L:한글`에 고정 그룹 `출력언어`, 패턴 `custom L:{option}`을 적용할 수 있다.
- [ ] named capture 정규식이 동작하며 문법이 잘못된 정규식은 저장되지 않고 한국어 오류를 표시한다.
- [ ] 두 규칙이 모두 일치할 때 위에 있는 규칙이 적용되고 `위로`·`아래로`로 순서를 바꿀 수 있다.
- [ ] 규칙을 비활성화하거나 삭제하면 미리보기와 검사 결과가 즉시 원래 상태로 돌아온다.

## 수동 지정과 동작 모드

- [ ] 이름 형식이 일정하지 않은 프롬프트를 목록에서 선택해 그룹·옵션을 수동 지정할 수 있다.
- [ ] 수동 지정된 프롬프트에는 `연결: 수동 지정`이 표시되고 이름 규칙보다 우선한다.
- [ ] 프롬프트 이름을 바꿔도 SillyTavern identifier가 같으면 수동 지정이 유지된다.
- [ ] `대안 그룹`은 내부 비교를 제외하고 여러 옵션이 포함되면 그룹 경고 한 건을 표시한다.
- [ ] `내부 무시`는 내부 비교와 다중 활성 그룹 경고를 숨기지만 그룹 밖 비교는 유지한다.
- [ ] `일반 그룹`은 그룹을 표시하면서 기존처럼 내부 비교도 수행한다.
- [ ] 검사 범위를 `language`로 지정하면 언어 비교만 제외되고 다른 범주의 비교는 유지된다.
- [ ] 제외된 비교 목록에 두 소스, `language` 같은 범주, 그룹과 제외 이유가 표시된다.

## 실제 포함 상태와 소스 정확성

- [ ] 설정상 비활성 프롬프트는 `설정상 비활성`으로 표시되고 충돌 비교에 참여하지 않는다.
- [ ] 설정상 활성이어도 현재 payload에 포함되지 않은 프롬프트는 `실제 요청에 미포함`으로 표시되고 비교에 참여하지 않는다.
- [ ] 같은 문장이 활성·비활성 프롬프트에 동시에 있어도 비활성 프롬프트가 활성 payload의 근거를 가져가지 않는다.
- [ ] system 역할로 설정한 프롬프트 문자열이 user 메시지에만 있을 때 실제 포함으로 잘못 연결되지 않는다.
- [ ] 설정 프롬프트로 연결되지 않은 실제 system/developer 요청 조각은 별도 요청 소스로 보인다.
- [ ] 대화 기록에 과거 언어 지시가 있어도 현재 시스템 지시 충돌로 잘못 집계되지 않는다.
- [ ] 관련 소스 이동과 최종 프롬프트 근거 이동이 실제 지시 문자열을 가리킨다.
- [ ] 근거 범위가 없는 결과에는 사용할 수 없는 최종 근거 이동 버튼이 나타나지 않는다.

## 기존 기능 회귀

- [ ] 일반 메시지를 보낸 뒤 새 스냅샷이 한 번만 추가된다.
- [ ] 두 생성을 빠르게 연속 실행해도 두 스냅샷의 모델·프롬프트가 서로 바뀌지 않는다.
- [ ] 채팅별 타임라인, 개별 삭제, 전체 비우기와 저장 실패 재시도가 동작한다.
- [ ] 밝은/어두운 테마에서 패널 배경이 불투명하고 비교 정책 표와 경고가 읽힌다.
- [ ] 모바일 폭에서 정책 입력이 한 열로 바뀌고 가로로 잘리지 않는다.
- [ ] 원본 소스↔최종 프롬프트 이동, diff, 로어북 변화, 검색이 기존처럼 동작한다.
- [ ] tool schema·호출·결과와 멀티모달 입력 소스가 표시된다.
- [ ] API 키·토큰·암호 계열 필드와 미디어 data URL 원문이 저장되지 않는다.
- [ ] JSON·TXT·Markdown 내보내기와 개인정보 제외 진단 보고서가 동작한다.
- [ ] Tab·Shift+Tab focus trap, Escape 닫기, 탭 화살표/Home/End 이동이 동작한다.

## 문제 보고 시 기록

- [ ] SillyTavern 버전, 브라우저, API 유형, provider, 모델과 생성 유형을 기록한다.
- [ ] 문제가 난 프롬프트의 표시 이름과 identifier, 설정상 활성 여부를 기록한다.
- [ ] 비교 정책의 템플릿 또는 정규식, 고정 그룹, 모드, 검사 범위를 기록한다.
- [ ] 미리보기의 실제 포함 상태와 제외된 비교 목록을 함께 기록한다.
- [ ] 가능하면 원문 스냅샷 대신 개인정보가 제외된 진단 JSON을 첨부한다.
