# v0.9.0 사용자 실사용 체크리스트

v0.9.0은 Rule Inspector V3의 구조 분석 기반을 추가한 대규모 검토 버전입니다. 자동 테스트와 로컬 브라우저 샌드박스 검토는 완료했지만 실제 프리셋의 다양한 한국어 문장과 SillyTavern 조립 결과는 사용자 환경에서 확인해야 합니다.

실제 API 키나 토큰을 테스트 데이터로 입력하지 마세요. 문제 보고에 프롬프트 원문이 필요하면 개인 정보와 캐릭터 설정을 제거한 최소 재현 문구만 사용하세요.

## 우선 확인할 핵심 시나리오

- [ ] 확장 목록과 ST DevTools 제목에 `v0.9.0`이 표시된다.
- [ ] 규칙 검사 탭의 `지시 구조 분석 V3`이 기본적으로 접혀 있어 기존보다 스크롤 압박이 늘지 않는다.
- [ ] V3 요약에 지시 원자 수, 충돌 관계 수와 필요한 경우 우선순위 경고 수가 구분되어 표시된다.
- [ ] V3를 펼치면 비교 가능한 지시 소스, 참고 데이터와 소스 검사 범위가 표시된다.
- [ ] `추출된 지시 원자`를 펼치면 응답 언어·출력 형식·역할·포함/금지 지시가 각각 별도 카드로 나타난다.
- [ ] 원자 카드에 대상·처리·우선순위·범위, source 역할·position·depth, 원문 문자 범위, 추출 방식과 신뢰도가 표시된다.
- [ ] 원자의 `추출 문구와 식별 정보`를 펼치면 실제로 감지한 최소 문구와 소스 ID를 확인할 수 있다.

## 판정 정확성

아래 문구는 폐기 가능한 테스트 프롬프트로 확인할 수 있습니다.

- [ ] 활성 소스 하나에 `반드시 한국어로 답변하세요.`를, 다른 활성 소스에 `Always respond in English.`를 넣으면 언어 충돌이 `확정`으로 표시된다.
- [ ] `일본인인 경우 일본어로 답변하세요.`처럼 조건이 붙은 지시와 다른 언어 지시가 만나면 `후보`로 표시되고 조건 문구가 원자에 남는다.
- [ ] 서로 다른 역할 선언은 정적 검사만으로 승자를 단정하지 않고 `근거 부족`으로 표시된다.
- [ ] `설명을 포함하세요.`와 `설명을 포함하지 마세요.`가 함께 있으면 긍정·금지 충돌 쌍이 생성된다.
- [ ] `이전 지시를 무시하세요.` 같은 명시적 문구는 별도 우선순위 경고로 표시된다.
- [ ] 검사 카드의 `관련 소스 보기`와 `최종 근거 보기`가 해당 소스·문자 위치로 이동한다.
- [ ] 한 충돌 묶음에 세 언어가 있으면 각 실제 충돌 쌍이 나타나고, 기술 ID 대신 언어 묶음의 지시·관계 개수가 표시된다.

## 오탐 방지 경계

- [ ] `예: "Always respond in English."`처럼 예시로 적은 문구는 실제 지시 원자나 충돌로 처리되지 않는다.
- [ ] fenced code block 안의 지시 예문은 실제 지시로 처리되지 않는다.
- [ ] 과거 채팅 메시지에 다른 언어 지시가 있어도 현재 지시 소스와 충돌하지 않는다.
- [ ] tool/function schema의 설명 문자열에 지시 표현이 있어도 일반 프롬프트와 충돌하지 않는다.
- [ ] 이미지·오디오·비디오 표시 소스가 지시 충돌에 참여하지 않는다.
- [ ] 비활성 또는 실제 요청에 포함되지 않은 설정 프롬프트가 원자·충돌·가장 큰 포함 소스에 들어오지 않는다.
- [ ] 참고 데이터의 문구는 검사 범위에서 구분되어 보이지만 일반 지시와 자동 충돌하지 않는다.

## 대안 프롬프트 비교 정책

- [ ] `출력언어 | 한국어`, `출력언어 | 일본어`, `출력언어 | 영어`와 `{group} | {option}` 규칙이 같은 대안 그룹으로 인식된다.
- [ ] 같은 대안 그룹 내부의 언어 원자 쌍은 충돌 관계를 만들지 않는다.
- [ ] 대안 그룹 밖에 있는 다른 언어 프롬프트와의 비교는 유지된다.
- [ ] 여러 옵션이 실제 요청에 동시에 포함되면 쌍별 충돌 대신 기존 그룹 경고 한 건이 표시된다.
- [ ] 비교 정책에서 언어 범주만 제외하면 형식·역할·지시·중복 범주의 기존 동작은 유지된다.
- [ ] 수동 지정과 이름 규칙을 바꾼 뒤 규칙 검사 결과가 즉시 새 정책을 반영한다.

## UI와 성능

- [ ] 약 420~430px 폭에서도 V3 요약·상태 배지·원자 메타데이터·근거 문구가 가로로 잘리지 않는다.
- [ ] 밝은/어두운/자동 테마에서 확정·후보·근거 부족 배지와 카드 왼쪽 상태선이 읽기 쉽다.
- [ ] V3·소스 검사 범위·원자 상세·근거를 반복해서 열고 닫아도 패널이 멈추지 않는다.
- [ ] 프롬프트가 매우 큰 경우 분석 상한 안내가 나타나며 패널을 계속 조작할 수 있다.
- [ ] 오래 사용한 채팅에서 규칙 검사 탭 전환, 비교 정책 저장과 스냅샷 전환이 수 초간 멈추지 않는다.

## 기존 기능 회귀

- [ ] 톱니바퀴의 보관 수·불러오기 수·테마 설정을 적용한 뒤 버튼이 다시 활성화되고 재차 저장할 수 있다.
- [ ] 불러오기 수만 바꾸면 전체 저장 스냅샷 수가 줄지 않는다.
- [ ] 보관 수를 낮출 때만 삭제 영향 확인이 나타나고, 취소하면 데이터가 유지된다.
- [ ] 스냅샷 개별·다중 삭제, 성장 그래프, 탐색기, 비교, 컨텍스트와 검색이 정상 동작한다.
- [ ] v0.8.8 이전 배열형 저장 데이터를 처음 여는 경우에도 스냅샷 ID와 Rule Inspector 결과를 읽을 수 있다.

## 문제 보고 시 기록

- [ ] SillyTavern 버전, 브라우저, API 유형, provider, 모델과 생성 유형을 기록한다.
- [ ] 기대 판정과 실제 판정(`확정`·`후보`·`근거 부족`), 적용한 비교 정책 범주를 함께 기록한다.
- [ ] 문제가 난 원자 카드의 속성·값·추출 방식·신뢰도와 소스 종류를 기록한다.
- [ ] 원문 전체 대신 오탐 또는 누락을 재현하는 최소 문장과 개인정보가 제외된 진단 JSON을 우선 첨부한다.
