# v0.9.2 사용자 실사용 체크리스트

v0.9.2는 새로 캡처한 요청에 구조 위치와 생성 경로를 기록하고, 소스·로어북 비교 정확도와 구버전 저장 데이터의 안전한 읽기 경계를 강화한 버전입니다. 자동 테스트와 로컬 샌드박스로 검토하더라도 실제 SillyTavern provider별 payload 구조와 오래 사용한 IndexedDB는 사용자 환경에서만 최종 확인할 수 있습니다.

실제 API 키·토큰·개인정보를 테스트 문구나 문제 보고에 포함하지 마세요. 내보낸 스냅샷 원문은 공유 전에 직접 검토해야 합니다.

## 먼저 확인할 핵심 8개

- [ ] 확장 목록과 ST DevTools 제목에 `v0.9.2`가 표시된다.
- [ ] 업데이트 후 일반 메시지를 한 번 생성하면 프롬프트 탐색기의 실제 포함 소스에 `구조 위치`가 표시된다.
- [ ] 구조 위치를 펼치면 JSON pointer와 가능한 경우 메시지 번호·role·값 범위·최종 범위가 표시된다.
- [ ] 컨텍스트의 `생성 경로`에서 전송 경로와 SillyTavern에서 선택한 생성 소스가 서로 구분된다.
- [ ] 공개 근거가 없는 upstream provider는 임의의 업체명 대신 `미확인`으로 표시된다.
- [ ] 같은 프롬프트의 배치 설정만 바꾼 두 스냅샷을 비교하면 해당 필드가 `배치 설정 변경`으로 표시된다.
- [ ] 같은 UID 로어북 항목의 내용만 바꾸면 활성화·제거가 아니라 `변경`으로 표시된다.
- [ ] 업데이트 전 스냅샷도 열리며, 당시 기록하지 않은 구조 위치는 추정값 대신 `이전 스냅샷 · 위치 기록 없음`으로 표시된다.

## 구조 위치 provenance

- [ ] Chat Completion 새 캡처에서 system·user·assistant 메시지 소스의 메시지 번호와 role이 실제 payload 순서와 맞는다.
- [ ] Text Completion 새 캡처에서도 구조 위치가 있으면 표시되고, 근거가 없으면 빈 위치를 만들어내지 않는다.
- [ ] tool/function schema·호출·결과와 멀티모달 조각의 JSON pointer가 해당 요청 항목을 가리킨다.
- [ ] 동일 문구가 여러 메시지에 있을 때 각 구조 위치가 서로 다른 메시지 번호로 구분된다.
- [ ] 구조 위치가 많은 소스는 최대 50곳만 렌더링하고 전체 위치 수와 생략 안내를 표시한다.
- [ ] `구조 위치`를 접은 상태에서는 긴 위치 목록 때문에 탐색기 스크롤이 불필요하게 길어지지 않는다.
- [ ] 기존 문자열 일치·정규화 일치·템플릿 추정 배지와 최종 프롬프트 강조 이동이 계속 동작한다.

## 생성 경로와 assistant prefill

- [ ] Chat Completion에서는 선택한 `chat_completion_source`와 그 요청 내 근거 위치가 표시된다.
- [ ] Text Completion에서는 generation type이 선택한 생성 소스로 표시된다.
- [ ] OpenRouter·사용자 지정 API처럼 내부 upstream을 공개 이벤트로 확인할 수 없는 경로는 선택 소스와 upstream을 동일시하지 않는다.
- [ ] 명시적인 prefill 설정을 사용하는 요청은 `프리필 확정`으로 표시된다.
- [ ] 명시적인 근거 없이 마지막 assistant 메시지 위치만 이용한 항목은 `프리필 추정`으로 표시된다.
- [ ] 일반 마지막 assistant 응답을 확정 prefill이라고 표시하지 않는다.

## 소스·로어북 비교

비교할 두 스냅샷은 한 번에 한 항목만 바꾸어 생성하면 결과를 확인하기 쉽습니다.

- [ ] 같은 설정 프롬프트의 role을 바꾸면 `role` 변경 전·후가 표시된다.
- [ ] depth 또는 position을 바꾸면 각각의 변경 전·후가 표시된다.
- [ ] 활성 상태나 Prompt Manager 순서만 바꾸어도 내용 변경과 구분된 배치 설정 변화가 표시된다.
- [ ] 실제 요청 포함 상태가 켜짐에서 꺼짐으로 바뀌면 기존처럼 삭제로 표시된다.
- [ ] 두 스냅샷에서 모두 비활성·미포함인 소스는 원문 내용 변화를 노출하지 않고 배치 메타데이터 변화만 표시한다.
- [ ] 동일 world·UID 로어북 항목의 내용·키·position·목록 순서 변화가 각 필드의 변경 전·후로 표시된다.
- [ ] 실제로 새로 활성화되거나 제거된 로어북 항목은 내부 변경과 별도 목록에 표시된다.

## 지연 마이그레이션과 손상 안전성

- [ ] v0.9.1 또는 더 오래된 스냅샷이 ID·시각·원문·토큰 정보를 유지한 채 열린다.
- [ ] 구버전 스냅샷을 연 뒤 패널을 닫고 다시 열어도 반복적인 장시간 변환이 발생하지 않는다.
- [ ] 구버전 스냅샷의 기존 연결 방식·신뢰도는 유지되고 새 구조 위치만 `기록 없음`으로 표시된다.
- [ ] 오래된 데이터가 있는 채팅에서도 저장 요약의 스냅샷 수와 대략적 용량이 비정상적으로 감소하지 않는다.
- [ ] 기존 데이터 중 읽지 못하는 레코드가 실제로 있을 때 다른 정상 스냅샷은 계속 표시되고 손상 개수 안내가 나타난다.
- [ ] 손상 안내에 프롬프트 원문·레코드 식별자·내부 오류 문자열이 표시되지 않는다.

손상 상황을 확인하기 위해 개발자 도구에서 IndexedDB를 임의로 편집하지 마세요. v0.9.2는 손상 원본을 보존하고 격리해 읽지만 자동 수정·삭제·백업 복원은 아직 제공하지 않습니다.

## UI와 기존 기능 회귀

- [ ] 약 420~430px 폭에서 구조 위치, 생성 경로, 배치 설정 변경 표와 로어북 변경 카드가 패널 밖으로 넘치지 않는다.
- [ ] 구조 위치와 변경 상세를 반복해서 접고 펼쳐도 패널이 장시간 멈추지 않는다.
- [ ] 밝은·어두운·자동 테마에서 새 상태 배지와 변경 전·후 값이 읽기 쉽다.
- [ ] 프롬프트 탐색기·타임라인·비교·컨텍스트·규칙 검사·검색 탭이 정상 동작한다.
- [ ] 비교 정책 프로필, 오탐·항상 무시·이번만 숨김과 정책 가져오기·내보내기가 유지된다.
- [ ] 보관 수·불러오기 수 설정, 개별·다중 삭제와 성장 그래프가 정상 동작한다.
- [ ] 설정 적용 뒤 적용 버튼이 다시 활성화되고 재차 저장할 수 있다.

## 문제 보고 시 기록

- [ ] SillyTavern 버전, 브라우저, Chat/Text Completion 구분, 선택한 source, 모델과 생성 유형을 기록한다.
- [ ] 새 캡처인지 v0.9.2 이전 스냅샷인지 기록한다.
- [ ] 구조 위치 문제는 기대한 JSON pointer·메시지 번호·role과 실제 표시값을 개인정보 없이 기록한다.
- [ ] diff 문제는 두 캡처 사이에 바꾼 role·depth·position·활성 상태·순서 또는 로어북 필드 하나를 기록한다.
- [ ] 저장 문제는 손상 개수 안내 여부와 정상 형제 스냅샷이 계속 열리는지만 기록하고 IndexedDB 원문은 공유하지 않는다.
- [ ] 원문 전체 대신 문제를 재현하는 최소 문장과 개인정보를 제거한 화면 또는 진단 보고서를 첨부한다.

## 다음 버전

v0.10.0은 기간·총용량 보관 정책, quota와 복구 흐름, 가상 스크롤·Worker 분석, 원문 제거본·메타데이터 전용 캡처와 안전한 공유·백업 기반을 구현할 예정입니다. v0.10.1의 usage 상관관계와 v0.11.0의 선택적 AI Semantic Inspector는 아직 구현되지 않았습니다.
