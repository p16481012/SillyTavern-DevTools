# v0.8.9 사용자 실사용 체크리스트

v0.8.9는 이후 Rule Inspector 기능이 늘어나도 패널이 다시 무거워지지 않도록 저장·로드·렌더링 기반을 바꾼 성능 업데이트입니다. 자동 테스트와 로컬 브라우저 샌드박스 검토는 완료했으며, 사용자는 실제 SillyTavern IndexedDB에서 아래 핵심 항목만 확인하면 됩니다.

실제 API 키나 토큰을 테스트 데이터로 입력하지 마세요. 민감 정보 검토가 필요하면 반드시 폐기 가능한 가짜 문자열을 사용하세요.

## 권장 5분 검토

- [ ] 확장 목록과 ST DevTools 제목에 `v0.8.9`가 표시된다.
- [ ] 제목 오른쪽 톱니바퀴를 누르면 `불러올 스냅샷 수` 설정 모달이 열린다.
- [ ] 값을 예를 들어 `5`로 적용하면 타임라인에 `전체 N개 중 최근 5개`가 표시되고 스냅샷 선택기·비교 선택지에도 최근 5개만 나타난다.
- [ ] 설정값을 줄여도 저장 상태의 전체 스냅샷 수와 과거 데이터는 줄어들지 않는다.
- [ ] 패널이나 SillyTavern을 다시 열어도 설정한 개수가 유지된다.
- [ ] 설정 모달에서 `Esc`를 한 번 누르면 모달만 닫히고 패널은 유지되며 포커스가 톱니바퀴로 돌아간다.
- [ ] 오래 사용한 채팅에서 패널 열기·새 메시지 생성 종료·탭 전환이 이전 버전보다 빠르고 수 초간 멈추지 않는다.
- [ ] 프롬프트 탐색기에서 닫힌 카드는 제목만 보이고 펼치면 원문과 연결 근거가 정상 표시된다.
- [ ] 컨텍스트의 요청 설정·요청 본문·프롬프트 payload를 펼쳤을 때 JSON 또는 원문이 정상 표시된다.
- [ ] 프롬프트 비교의 소스별 변경과 전체 문자 변경을 펼쳤을 때 추가·삭제·수정 색상과 내용이 정상 표시된다.

## 이전 저장 데이터 마이그레이션

첫 접근에서는 v0.8.8까지의 채팅별 배열을 스냅샷별 레코드로 한 번 옮기므로 데이터 양에 따라 평소보다 오래 걸릴 수 있습니다.

- [ ] 업데이트 전 스냅샷이 있던 채팅을 처음 열면 최신 항목과 전체 보관 수가 유지된다.
- [ ] 첫 접근이 끝난 뒤 패널을 닫았다 다시 열면 같은 변환 지연이 반복되지 않는다.
- [ ] 이전 스냅샷의 탐색기·비교·컨텍스트·규칙 검사 내용과 ID가 유지된다.
- [ ] 변환 중 브라우저를 닫는 상황이 생겨도 다음 실행에서 다시 열 수 있으며 중복 스냅샷이 생기지 않는다.

## 성능 설정 선택 가이드

- 일반 사용: 기본값 `20`
- 최근 흐름만 빠르게 확인: `5~10`
- 긴 타임라인 비교: `30~50`
- 저장된 전체 범위를 항상 탐색: `100`

이 값은 패널이 자동으로 읽는 범위입니다. 채팅당 보관 상한은 계속 100개이며, 현재 채팅 전체 진단 또는 전체 채팅 진단처럼 사용자가 명시적으로 실행한 내보내기는 저장된 전체 범위를 읽을 수 있습니다.

## 중요 기능 회귀

- [ ] `출력언어 | 한국어`, `출력언어 | 일본어`, `출력언어 | 영어`와 `{group} | {option}` 비교 정책이 같은 대안 그룹으로 인식된다.
- [ ] 같은 그룹 내부 비교는 제외되지만 그룹 밖 프롬프트와의 비교는 유지된다.
- [ ] 비활성 또는 실제 요청 미포함 프롬프트가 비교·가장 큰 포함 소스·규칙 충돌에 들어오지 않는다.
- [ ] 스냅샷 개별·다중 삭제 후 현재 로드 범위가 다시 채워지고 전체 개수가 정확히 줄어든다.
- [ ] 성장 그래프, 원본↔최종 위치 이동, 검색과 규칙 근거 이동이 정상 동작한다.
- [ ] 밝은/어두운 테마와 약 420px 모바일 폭에서 설정 모달·탭·카드가 가로로 잘리지 않는다.

## 문제 보고 시 기록

- [ ] SillyTavern 버전, 브라우저, API 유형, provider, 모델과 생성 유형을 기록한다.
- [ ] 톱니바퀴에 설정한 로드 수, 해당 채팅의 전체 스냅샷 수와 문제가 첫 마이그레이션 중인지 기록한다.
- [ ] 저장 상태에 표시된 backend와 문제가 난 캡처의 요청·생성 상태를 기록한다.
- [ ] 가능하면 원문 스냅샷 대신 개인정보가 제외된 진단 JSON을 첨부한다.
