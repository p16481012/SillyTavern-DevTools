# v0.10.0 사용자 실사용 체크리스트

v0.10.0은 저장 정책·개인정보 모드·백업/복원 경계가 바뀐 대규모 검토 버전입니다. 알고리즘 불변식은 자동 테스트로, 화면 배치와 결정적 오류 상태는 로컬 샌드박스로 검사했습니다. 아래에는 실제 SillyTavern·브라우저 IndexedDB·provider 조합에서만 확인할 수 있는 항목을 남깁니다.

## 시작 전

- [ ] ST DevTools 제목에 `v0.10.0`이 표시된다.
- [ ] 중요한 스냅샷이 있다면 먼저 `전체 원문 백업`을 내려받아 로컬 비공개 위치에 보관한다.
- [ ] 전체 원문 archive에는 시스템 프롬프트·캐릭터/로어 설정·채팅 ID가 들어갈 수 있다는 경고를 확인하고 파일을 공유하지 않는다.
- [ ] 삭제·전체 교체 검사는 실제 보관분이 아닌 별도 테스트 채팅 또는 테스트 브라우저 프로필에서 한다.

## 저장 정책과 실제 IndexedDB

- [ ] 업데이트 직후 기존 v0.9.x 스냅샷 수와 대표 스냅샷 원문이 그대로 열린다.
- [ ] `불러올 수`만 바꾸면 화면 목록만 달라지고 저장 상태의 전체 스냅샷 수는 줄지 않는다.
- [ ] 보관 기간·채팅별 개수·전체 용량을 낮추면 삭제 전에 대상 개수·채팅 수·대략적 용량이 표시되고, 취소하면 아무것도 삭제되지 않는다.
- [ ] 테스트 데이터에서 적용을 승인하면 `기간 → 채팅별 개수 → 전체 용량` 순서에 맞게 오래된 항목이 줄고 각 채팅의 최신 정상 스냅샷은 남는다.
- [ ] 설정을 매우 낮춰도 보호 항목 때문에 초과 상태가 남는 경우 이를 오류 없이 설명한다.
- [ ] 저장 상태에서 `ST DevTools 추정치`와 `브라우저 오리진 전체` 사용량·quota가 다른 범위로 표시되며 둘을 확장 전용 수치처럼 합치지 않는다.

## 무결성 진단

- [ ] 정상 저장소에서 진단을 실행하면 정상 또는 제한된 집계 결과가 나오고 패널이 멈추지 않는다.
- [ ] 복구가 필요하다고 표시된 경우 전체 원문 백업을 먼저 만든 뒤 미리보기 개수와 복구 확인 문구를 검토한다.
- [ ] 승인 후 정상 스냅샷이 계속 열리고 새 캡처가 저장되며, 새로고침 뒤 저장 요약도 일치한다.
- [ ] 손상 상세의 raw 원문·snapshot ID·chat ID가 알림이나 화면에 노출되지 않는다.

개발자 도구에서 IndexedDB를 임의로 손상시키거나 quota를 고의로 가득 채우지 마세요. 누락 참조·고아 재인덱싱·구버전 중복 제거·충돌 raw 보존은 자동 테스트로 검증하며, 실제 오류가 자연스럽게 발생했을 때만 재현 절차를 기록합니다.

## 개인정보 모드

각 모드를 선택한 뒤에는 **새 메시지를 한 번 생성**해야 합니다. 설정 변경은 과거 full 스냅샷을 자동 변환하지 않습니다.

### 전체 원문

- [ ] 새 스냅샷에서 탐색기·비교·컨텍스트·규칙 검사·검색이 기존처럼 동작한다.
- [ ] 전체 원문 포함 경고가 표시되고 일반 내보내기·전체 backup을 공유하지 않도록 안내한다.

### 원문 제거본

- [ ] 새 스냅샷에 원문 제거 안내가 표시되고, 원문이 필요한 규칙 검사·검색은 사용 불가 안내로 막힌다.
- [ ] 공유용 redacted JSON을 열어 실제 프롬프트 문장이 없고 길이·바이트·SHA-256 placeholder만 남았는지 직접 검색한다.
- [ ] `원문 제거본`이 이름·이메일 같은 개인정보를 의미적으로 탐지하는 기능이 아니라 원문 문자열 제거 방식이라고 명확히 안내한다.

### 메타데이터만

- [ ] 새 스냅샷에서 시각·provider·model·토큰·소스/로어 개수 같은 제한된 요약만 보인다.
- [ ] 탐색기·비교·컨텍스트·규칙 검사·검색을 열면 복원할 원문 구조가 없다는 안내가 나온다.
- [ ] metadata 공유 JSON에 payload·request body·sources·lore 원문이 없는지 직접 확인한다.

## 백업·병합·복원

- [ ] full·redacted·metadata 스냅샷이 섞인 상태에서 전체 archive를 만들면 mixed 보관분이라는 경고와 모드별 개수가 맞다.
- [ ] 별도 테스트 프로필에서 기본 `병합`으로 가져오면 기존 스냅샷은 남고 새 항목만 추가된다.
- [ ] 같은 archive를 다시 병합하면 동일 digest 항목을 중복 생성하지 않는다.
- [ ] 같은 ID에 다른 내용이 있는 테스트 archive는 선택한 `둘 다 유지` 또는 `건너뛰기` 정책대로 처리된다.
- [ ] `전체 교체`는 archive별 확인 문자열을 정확히 입력하기 전에는 실행되지 않는다.
- [ ] 전체 교체 성공 뒤 새로고침해도 archive 내용이 유지되고 교체 전 테스트 항목은 사라진다.
- [ ] 가져오기 실패가 발생하면 성공으로 표시하지 않고, 기존 항목이 다시 열리는지 확인한 뒤 추가 작업 없이 문제를 보고한다.

## 진단 비교

- [ ] 같은 범위의 진단 JSON 두 개를 선택하면 스냅샷·모델·토큰 집계의 증감 요약이 표시된다.
- [ ] 현재 채팅 보고서와 전체 채팅 보고서처럼 범위가 다르면 비호환 경고가 나온다.
- [ ] 비교 화면에 원문 prompt·request body·원시 snapshot/chat ID가 나타나지 않는다.

## 실제 provider와 성능

- [ ] 사용 중인 대표 Chat Completion provider에서 새 스냅샷의 선택 소스·model·구조 위치·assistant prefill 상태가 실제 요청과 맞다.
- [ ] 대표 Text Completion provider에서도 생성 유형·prompt 경계와 lifecycle이 맞다.
- [ ] OpenRouter·사용자 지정 API의 내부 upstream은 근거 없이 특정 업체명으로 표시되지 않고 `미확인`으로 남는다.
- [ ] 100개 이상을 실제로 보관하는 경우 타임라인과 대형 소스 목록을 빠르게 스크롤해도 패널이 장시간 멈추지 않고 선택·키보드 이동이 유지된다.
- [ ] Worker가 제한된 브라우저 환경에서도 검색·diff·규칙 검사가 실패 상태를 설명하거나 제한된 fallback으로 끝나며 무한 로딩하지 않는다.

## 비공개 모드·quota 환경

- [ ] 평소 사용하는 브라우저 프로필에서 저장 backend가 IndexedDB인지 임시 메모리인지 확인한다.
- [ ] 비공개 창 또는 저장이 제한된 환경에서 임시 메모리라면 새로고침 시 소실 경고가 표시된다.
- [ ] quota 부족 또는 저장 실패 알림이 나오면 같은 스냅샷 재시도가 가능하고, 실패 중에 보관 수·archive 전체 교체를 반복하지 않는다.

## 문제 보고 시 남길 정보

- [ ] SillyTavern·ST DevTools·브라우저 버전, 일반/비공개 창 여부를 기록한다.
- [ ] Chat/Text Completion, 선택한 source, model, 캡처 privacy mode를 기록한다.
- [ ] 저장 문제는 IndexedDB/메모리 상태, 정책 값, 미리보기와 적용 결과의 **개수만** 기록한다.
- [ ] 복원 문제는 merge/replace, conflict 정책, archive schema와 mixed 여부, 표시된 오류 code를 기록한다.
- [ ] prompt 원문·API key·전체 archive·IndexedDB raw 값은 이슈에 첨부하지 않는다.
