# ST DevTools

ST DevTools는 SillyTavern용 읽기 전용 프롬프트 파이프라인 디버거입니다. 일반 채팅 프롬프트를 변경하지 않으면서 조립된 프롬프트와 생성 설정을 로컬에 캡처하고, 프롬프트·기록·비교·규칙 검사·검색과 사용자가 매번 명시적으로 동의하는 선택적 AI 의미 검사를 제공합니다.

## 현재 버전

`v0.12.4`

v0.12.4는 캐릭터 그리팅처럼 활성 여부가 확인되지 않은 미연결 소스를 활성 프롬프트로 잘못 안내하던 문제를 고치고, 모바일 설정 패널의 내부 여백을 줄인 UI 패치입니다. v0.12.3의 위치 이동·AI 검사 연속성·컨텍스트 한도·성장 그래프 보강은 그대로 유지합니다.

주요 기능:

- Magic Wand 메뉴에서 실행
- `전송 프롬프트`·`기록`·`변경 비교`·`규칙 검사`·`검색` 다섯 기능을 한 번에 보여 주는 고정 하단 단층 내비게이션
- 전송 프롬프트 안에서 기본 접힌 전체 프리셋과 `요청 포함만` 필터, 생성 설정과 원본 프롬프트 payload 확인
- 총 토큰·컨텍스트 사용률·남은 컨텍스트·provider/model·현재 요청 선택을 모은 첫 화면 요약 카드
- 모바일 `100vw`·`100dvh` 앱 셸과 모바일에서 데스크톱 geometry 복원·저장 및 창 드래그를 막는 분리된 동작
- 44px 모바일 헤더 터치 영역과 뒤에 선언된 강한 호스트 테마에도 유지되는 밝은/어두운 입력창 대비
- 각 화면의 실제 기능 이름 제목과 PC hover·키보드 focus·모바일 click 설명 tooltip
- 헤더 이름 옆 상태 점과 짧은 상태 문구로 캡처 대기·처리·저장·실패 구분
- 요약 제목 좌측 정렬, 시각 크기를 줄인 hover·focus·click 도움말
- SillyTavern 테마 규칙과 격리된 내부 고대비 밝은/어두운 색 토큰
- 설정 진입 시 입력칸 자동 포커스를 피하고 상단 닫기·펼쳐진 자주 쓰는 설정을 제공하며, 테마 선택은 별도 저장 없이 즉시 유지
- 검사 화면에서 로컬 정적 결과와 선택적 AI 결과 모드를 전환하고 연결 프로필·응답 상한을 함께 설정. AI 모드를 켜는 것만으로는 아무 요청도 전송하지 않음
- 좁은 화면에서도 변경 내용을 읽을 수 있는 간결한 프롬프트 비교 표
- SillyTavern 테마 자동 감지 또는 사용자가 고정한 밝은/어두운 완전 불투명 패널과 테마별 고대비 상태색
- 드래그·크기 조절이 가능한 한국어 UI
- 읽기 전용 상태 표시
- Chat Completion 및 Text Completion 요청 준비 시점 캡처
- 요청 모델·sampler·출력 설정과 민감 정보 제거 기록
- 캡처 경계와 사용한 SillyTavern 이벤트 표시
- 요청 본문 캡처·prompt-only 시간 초과와 생성 시작·종료·사용자 중단 상태 구분
- 크기와 수명이 제한된 불투명 generation ledger로 동시에 진행되는 생성의 prompt·request·lore·lifecycle·usage 상태 격리
- prompt와 request 양쪽에 같은 공개 식별자가 실제로 있으면 정확히 연결하고, 충돌하거나 한쪽만 있으면 실패로 닫힘
- 공개 식별자가 없는 prompt→request 연결에만 프롬프트 유형별 FIFO를 사용하며 response usage에는 FIFO를 사용하지 않음
- 로컬 prompt tokenizer의 입력 추정치, 조건을 만족한 `MESSAGE_RECEIVED` 출력 추정치, provider 보고·미연결·산정 불가 usage 상태 분리
- prompt tokenizer가 5초 안에 끝나지 않으면 같은 패널 세션은 UTF-8 byte/3.35 로컬 추정으로 전환하고, 개인정보 변환·저장은 각각 30초 안에 성공 또는 실패로 종결
- provider가 응답에 명시해 스냅샷에 저장된 비용만 표시하며 로컬 가격표나 비용 추정은 사용하지 않음
- 캐릭터 카드의 시스템 프롬프트·후처리 지시·예시 대화·첫 메시지·깊이 프롬프트 분리
- 설정 프롬프트의 설정상 활성 상태와 실제 요청 포함 상태 분리
- Prompt Manager의 실제 배치 순서와 활성 상태를 이용한 프리셋 프롬프트 정렬
- 설정 프롬프트와 연결되지 않은 실제 system/developer 요청 조각 보존
- tool/function schema·호출·결과 전용 소스
- 이미지·오디오·비디오·파일 입력 전용 소스와 제공자별 토큰 추정 방식 표시

- payload의 JSON pointer·메시지 번호·role·원본 값 범위·최종 프롬프트 범위를 함께 보존하는 구조 위치 provenance

- 공개 Connection Manager profile `sendRequest()` 또는 현재 연결 `getContext().generateRaw()` 중 한 경로만 사용하는 provider adapter, 제한된 메모리 전용 결과 cache와 exact ticket 호출의 자기 캡처를 막는 nonce gate

- 제목 옆 작은 도움말 아이콘의 PC hover·키보드 focus·모바일 click 설명과 입력 문맥별 안내
- 패널 경계를 벗어나지 않는 도움말과 마침표별 화면 설명·예시 문단 분리
- API 전송 계열과 SillyTavern에서 선택한 Chat Completion·Text Completion 생성 소스를 구분한 화면·내보내기·진단 표시
- 전송 경로·SillyTavern에서 선택한 생성 소스·확인할 수 없는 upstream provider를 구분한 생성 경로 표시
- 요청 구조로 확인한 assistant prefill과 마지막 assistant 메시지 위치로 추정한 후보의 상태 분리
- 공백·문장 경계를 우선하고 한글 단어를 임의로 자르지 않는 공통 줄바꿈
- 모달 포커스 트랩, 탭 좌우/Home/End 이동, 성장 그래프 포인트 키보드 탐색

## 캡처 정확성과 경계

가능한 경우 다음 요청 설정 이벤트를 우선 사용합니다.

- `CHAT_COMPLETION_SETTINGS_READY`
- `TEXT_COMPLETION_SETTINGS_READY`
- `GENERATE_AFTER_DATA`

이 이벤트에서 모델·sampler·프롬프트가 포함된 SillyTavern 프런트엔드의 백엔드 요청 데이터를 복제합니다. 같은 이벤트 전달 중의 동기적 설정 변경이 반영될 수 있도록 리스너 반환 직후 복제하며, 원본 객체는 수정하지 않습니다.

해당 이벤트를 제공하지 않는 구버전 또는 특수 생성 경로에서는 다음 prompt-ready 이벤트를 대체 경계로 사용합니다.

- `CHAT_COMPLETION_PROMPT_READY`
- `GENERATE_AFTER_COMBINE_PROMPTS`

각 스냅샷은 실제로 사용한 이벤트와 경계를 기록합니다. 캡처된 요청은 SillyTavern 프런트엔드가 자체 백엔드로 전달하는 데이터이며, 백엔드 또는 provider 내부에서 이루어지는 후처리까지 포함한다고 보장하지 않습니다.

v0.9.2의 생성 경로는 전송 API·프롬프트 형식·생성 유형과 SillyTavern에서 선택한 Chat Completion source 또는 Text Completion generation type을 분리해 기록합니다. 선택 소스의 요청 내 근거 위치도 함께 표시하지만, OpenRouter나 사용자 지정 API 내부에서 실제 요청을 처리한 upstream provider는 공개 이벤트에 근거가 없으므로 `미확인`으로 남깁니다.

v0.10.1은 generation마다 불투명한 내부 handle을 만들고 pending prompt·request·lore·lifecycle·usage를 제한된 원장에 격리합니다. prompt와 request 양쪽에 같은 공개 ID가 실제로 존재할 때만 ID로 정확히 연결합니다. 같은 ID가 충돌하거나 한쪽 근거만 있으면 어느 생성에도 임의 연결하지 않습니다. 공개 ID가 없는 FIFO는 prompt와 request를 연결하는 호환 경로에만 쓰며, response usage를 생성에 붙이는 근거로 사용하지 않습니다.

현재 공식 SillyTavern 공개 이벤트 계약에는 provider 응답 usage와 그 응답을 특정 generation에 연결할 provider request ID가 없습니다. 따라서 기본 capability matrix는 공개 response·stream usage와 provider 비용을 `지원 안 함`으로 표시합니다. 별도 공개 integration이 응답과 같은 ID를 제공하는 경우를 위한 엄격한 parser·adapter는 있지만, 공식 이벤트만 사용하는 기본 설치에서는 provider usage를 캡처했다고 주장하지 않습니다.

새 스냅샷의 입력 토큰은 로컬 prompt tokenizer 결과를 `local-estimate`로 기록합니다. 출력 토큰은 `MESSAGE_RECEIVED` 메시지에 유효한 `extra.token_count`가 있고 generation type으로 하나의 활성 generation만 안전하게 고를 수 있을 때만 같은 스냅샷에 원자적으로 합칩니다. 겹친 생성 때문에 대상을 하나로 정할 수 없거나 값이 없으면 `unlinked` 또는 `unavailable`로 남기며 다른 generation의 값으로 메우지 않습니다.

API 키·인증 토큰·비밀번호·쿠키 등으로 판단되는 필드뿐 아니라 토큰 형태 값, Authorization 값, URL query의 비밀값과 PEM 개인 키도 저장 전에 제거합니다. 요청 본문뿐 아니라 캡처에 사용되는 캐릭터·설정 프롬프트·로어북·payload에도 같은 정제를 적용합니다.

## 규칙 검사

규칙 검사는 다음 항목을 로컬에서 확인합니다.

- 여러 소스에 중복된 문장
- 한 소스 안에서 반복되는 문장
- 한국어·영어·일본어·중국어 응답 지시 충돌
- JSON·XML·Markdown·일반 텍스트 출력 형식 충돌
- 여러 역할 선언
- 동일 대상에 대한 긍정·금지 지시 충돌
- 앞선 지시를 무시하거나 덮어쓰라는 명시적 문구
- 단일 소스의 과도한 토큰 점유
- 높은 컨텍스트 사용률
- 최종 프롬프트와 연결되지 않은 소스

v0.9.0부터 명시적인 지시 문구는 `대상·행동·속성·값·긍정/금지·범위·조건·예외·우선순위` 원자로 먼저 분해됩니다. 각 원자는 소스·문자 범위·role·position·depth·추출 방식·신뢰도를 보존하며, 충돌은 실제 원자 쌍과 연결된 클러스터로 표시됩니다. 조건이나 예외가 있으면 `후보`, 역할처럼 정적 패턴만으로 양립 여부를 확정하기 어려우면 `근거 부족`으로 낮춰 표시합니다.

대화 기록, 도구 schema·호출·결과, 멀티모달 표시와 최종 합성 결과는 지시 소스 간 충돌 비교에서 분리합니다. 참고 데이터는 원자를 추출할 수 있어도 일반 지시와 자동 충돌시키지 않습니다. 검사량은 패널 응답성을 위해 원자 500개·충돌 관계 200개·우선순위 경고 100개로 제한하며, 상한에 도달하면 화면에 생략 안내를 표시합니다.

정적 검사는 자연어의 의미 전체를 이해하지 못합니다. 현재 구조화 대상은 명시적인 언어·형식·역할·포함/금지·이전 지시 무시 표현이며, 말투·캐릭터 정체성·안전·메모리 지시의 의미 판단이나 실제 우선순위 승자 결정은 아직 하지 않습니다. 결과는 검토 보조 자료이며 프롬프트 품질을 보증하지 않습니다.

규칙 활성화와 수치 임계값은 현재 브라우저 프로필 전체에 적용됩니다. 비교 정책은 `채팅 → 캐릭터 → 프리셋 → 전체` 순서의 범위 프로필을 지원하며, 좁은 프로필에서 일치하는 수동 지정이나 이름 규칙이 없으면 더 넓은 프로필로 내려가 찾습니다. 한 프로필 안에서는 수동 지정이 이름 규칙보다 우선합니다. 모든 설정은 브라우저 로컬 저장소에만 보관되고 SillyTavern 프롬프트·캐릭터 카드·생성 설정을 변경하지 않습니다.

프리셋 API와 캐릭터·그룹 채팅 소유자를 포함한 정확한 범위 지문값은 v0.9.1의 새 캡처부터 기록됩니다. 이전 스냅샷도 전역 정책으로 다시 분석할 수 있지만, 프리셋·캐릭터·채팅 범위의 격리 검토에는 업데이트 뒤 새로 만든 스냅샷을 사용해야 합니다.

### 쉬운 시작과 작업 중심 탐색

하단 내비게이션은 `전송 프롬프트`·`기록`·`변경 비교`·`규칙 검사`·`검색` 다섯 기능을 항상 같은 순서로 보여 줍니다. 그룹을 먼저 고르거나 마지막으로 열었던 하위 기능을 추측할 필요 없이 어느 화면에서나 한 번에 직접 이동합니다. 중앙 콘텐츠만 스크롤되고 하단 내비게이션은 고정됩니다. 각 화면 위에는 실제 기능 이름을 제목으로 표시하고 설명은 제목 옆 작은 tooltip에서 PC hover·키보드 focus·모바일 click으로 확인합니다.

전송 프롬프트는 전체 프리셋을 Prompt Manager 순서로 보되 처음에는 접힌 상태로 시작합니다. `요청 포함만` 전환 버튼을 켜면 실제 payload에 연결된 프리셋만 남습니다. 소스의 `최종 위치 보기`는 접힌 최종 프롬프트를 먼저 열고 해당 범위로 이동하며, 소스 카드와 최종 범위는 같은 식별 색을 사용합니다. 독립 탭에서 제거한 생성 설정과 프롬프트 payload는 이 화면 아래의 요청 원본 disclosure에서 확인합니다.

모바일에서는 패널을 `100vw`·`100dvh` 앱 셸로 표시하고 하단 safe area를 보존합니다. 데스크톱에서 저장한 창 크기·위치를 모바일에 복원하지 않고 모바일 geometry도 저장하지 않으며, 헤더를 끌어 창을 이동하는 동작도 시작하지 않습니다. 데스크톱에서는 기존 크기 조절·위치 저장과 드래그를 유지합니다. 첫 스냅샷이 없을 때는 빠른 시작 순서를 표시하고 헤더에는 이름 옆 상태 점과 새로고침·설정·닫기 버튼을 유지합니다.

설정은 열 때 입력칸을 자동으로 잡지 않고 패널 자체로 포커스를 옮깁니다. 상단 닫기 버튼을 유지하며 자주 쓰는 항목은 바로 보여 주고 고급 항목만 접습니다. 테마는 선택하는 즉시 로컬에 저장되어 별도의 적용 버튼까지 스크롤할 필요가 없습니다. AI 사용 여부·연결 프로필·응답 상한은 일반 설정에서 제거하고 규칙 검사의 AI 모드 안에 모았습니다. AI 모드를 켜는 것만으로 provider 요청이 발생하지 않으며 대상 선택·전송 미리보기·호출별 동의 절차를 그대로 거쳐야 합니다.

밝은/어두운 내부 색 토큰과 패널 범위 스타일 격리로 공격적인 SillyTavern 호스트 테마가 상태색·버튼·표 구조를 덮어쓰는 영향을 줄였습니다. 좁은 화면의 프롬프트 비교는 같은 데이터를 간결한 표 형태로 재배치합니다. 현재 빠른 시작과 도움말은 완성된 온보딩이 아니며 코치마크·워크스루는 실제 사용성 검토 뒤 별도 버전에서 설계합니다.

캡처 중에는 짧은 상태 표시로 일반 요청의 진행·저장 여부와 AI 의미 검사 요청의 의도적 제외를 구분합니다. 이 상태에는 프롬프트 원문, 스냅샷·채팅 ID, provider/model이나 오류 메시지가 포함되지 않습니다. 일반 캡처는 모든 비동기 경로에서 `저장됨` 또는 `실패`로 종결합니다. SillyTavern prompt tokenizer가 5초 동안 응답하지 않으면 패널 세션의 공유 probe를 사용할 수 없음으로 표시한 뒤 UTF-8 byte/3.35 추정으로 계속 저장하고, 개인정보 변환과 저장소 작업은 각각 30초 제한을 둡니다. AI gate 탐색은 최대 2MiB·8,192개 노드·4,096개 문자열로 제한하며, 이를 넘겨 AI 요청 여부를 확인할 수 없으면 원문 유출을 막기 위해 저장하지 않는 fail-closed 경계를 유지합니다.

### 선택적 AI 의미 검사

v0.11.0의 **AI 의미 검사**는 정적 Rule Inspector를 대체하지 않는 선택 기능이며 신규·기존 사용자 모두 기본값은 꺼짐입니다. v0.12.2부터 규칙 검사 화면에서 AI 모드를 켜고 현재 정적 finding 또는 지시 클러스터를 체크해야만 `전송 내용 미리보기` 버튼이 활성화됩니다. 자동 선택, 백그라운드 호출, 자동 수정은 없습니다.

미리보기는 선택 대상의 관계 closure에 실제로 필요한 활성 소스 원문 전체만 표시합니다. 소스 이름·정확한 전송 문자열·선택한 연결 프로필 또는 현재 연결에서 확인한 provider/model·제외된 소스와 이유·예상 입력 토큰·응답 토큰 상한·고정 지시·추가 지시·프리필을 보여 줍니다. 필수 소스에 민감 토큰이 발견되면 일부를 가리고 보내지 않고 전체 준비를 실패로 닫습니다. `원문 제거본`과 `메타데이터만` 스냅샷에는 원문을 복원하거나 우회하지 않으며 AI 검사를 시작하지 않습니다.

설정의 `AI 연결 프로필`은 SillyTavern이 공개한 `ConnectionManagerRequestService`의 지원 프로필 이름만 나열합니다. ST DevTools 설정에는 최대 256자의 불투명 profile ID만 저장하며 프로필의 API 키·URL·비밀번호·proxy 설정을 읽거나 복제하지 않습니다. 목록을 일시적으로 읽지 못해도 기존 선택 ID는 화면에 노출하지 않은 채 보존합니다. Text Completion 프로필은 동의한 semantic prompt 문자열을 그대로 전달하고 별도 instruct 재구성을 끄며 sampler preset만 사용합니다. 프로필 API를 지원하지 않거나 저장한 프로필이 사라졌으면 요청 시작 전 현재 채팅 연결을 사용합니다. 미리보기 뒤에는 provider/model과 현재 연결/프로필 경로 및 profile ID가 그대로인지 다시 확인하고 다른 프로필의 cache도 분리합니다. 선택한 프로필로 요청을 시작한 뒤 실패한 경우에는 현재 연결로 자동 재시도하지 않으므로 한 번의 검사에서 두 provider에 과금될 가능성을 만들지 않습니다.

동의 체크는 미리보기를 열 때마다 선택 해제 상태로 초기화됩니다. 사용자가 이번 1회 전송에 동의하기 전에는 provider 호출이 없고, 취소하면 아무 것도 보내지 않습니다. 재시도도 provider/model과 전송 범위를 다시 준비하고 새 미리보기·새 동의를 요구합니다. 준비 시점과 전송 직전에 현재 provider/model identity를 다시 확인하며 값이 바뀌면 요청을 중단합니다. provider 자체를 확인할 수 없으면 지원하지 않는 상태로 닫고, provider만 확인되는 partial 상태는 model·비용을 추측하지 않은 채 그대로 보여 줍니다.

실행은 선택한 프로필이 있으면 SillyTavern의 공개 Connection Manager `sendRequest()`를, 그렇지 않으면 공개 `getContext().generateRaw()`를 사용하며 한 검사에서 두 경로를 연속 호출하지 않습니다. 응답은 추가 필드가 없는 버전 지정 JSON이어야 하고, 모든 target/source/atom/relation ID가 준비된 요청에 존재해야 합니다. 각 근거의 시작·끝 offset과 quote가 실제 전송 원문의 정확한 substring인지 확인하며 하나라도 맞지 않으면 응답 전체를 폐기합니다. 통과한 결과도 별도의 **AI 제안 — 자동 적용되지 않음** 영역에만 표시하며 정적 finding, 유효·오탐 판정, 비교 정책, 항상 무시 설정과 SillyTavern 원본을 변경하지 않습니다.

준비 선택과 AI 결과 cache는 현재 패널 메모리에만 있고 새로고침하면 사라집니다. cache는 전체 raw prompt·전체 raw provider response와 전용 `source.content`·`evidence.quote` 필드를 보관하지 않지만, 검증을 통과한 title·summary·rationale 같은 정규화 제안 텍스트는 제한된 메모리 TTL 동안 유지합니다. 모델이 이 제안 텍스트에 입력 원문의 표현을 반복할 가능성까지 제거하는 개인정보 필터는 아니므로 민감한 원문을 보내면 안 됩니다. 취소와 시간 제한은 UI가 늦은 결과를 무시하는 논리적 취소입니다. 이미 provider에서 시작된 계산을 강제로 중단하거나 과금이 발생하지 않았음을 보장하지 않으므로 전송 전 미리보기와 상한을 확인해야 합니다. AI 호출에는 호출별 nonce ticket과 exact duplicate 기억을 적용해 prompt·prompt type이 정확히 일치한 semantic 호출 이벤트만 자기 캡처에서 제외합니다. 동시에 진행된 식별자 없는 사용자 요청과 안전하게 구분할 수 없으면 어느 쪽에도 추측 연결하지 않습니다.

### 대안 프롬프트 비교 정책

서로 선택지인 프롬프트는 **규칙 검사 → 비교 정책**에서 같은 그룹으로 묶을 수 있습니다.

- `출력언어 | 한국어` 형식: 템플릿 `{group} | {option}`
- `[출력언어] 한국어` 형식: 템플릿 `[{group}] {option}`
- `출력언어❤️한국어` 형식: 템플릿 `{group}❤️{option}`
- `custom L:한글` 형식: 고정 그룹 `출력언어`, 템플릿 `custom L:{option}`
- 이름 형식이 일정하지 않으면 현재 스냅샷에서 프롬프트를 직접 수동 지정

`대안 그룹`은 같은 그룹 내부의 언어·형식·역할·지시·중복 비교만 건너뛰며 그룹 밖의 프롬프트와는 계속 비교합니다. 여러 옵션이 실제 요청에 동시에 포함되면 쌍별 충돌 대신 그룹 경고 한 건을 표시합니다. 이 경고까지 숨기려면 `내부 무시`를 선택합니다. 수동 지정이 이름 규칙보다 우선하고, 이름 규칙은 위에서부터 처음 일치한 항목만 적용됩니다.

v0.9.1에서는 그룹 동작을 먼저 정의한 뒤 여러 이름 규칙과 수동 지정에서 재사용합니다. 저장 전 `현재 스냅샷 미리보기`에서 검사 결과의 증감과 정책 배정 변화를 확인할 수 있습니다. 검사 결과는 `유효`·`오탐`으로 판정하거나 적용 가능한 특정 프로필 범위에서 항상 무시할 수 있고, `이번만 숨김`은 현재 패널 세션에만 유지됩니다.

자세한 설정 예시는 [`docs/RULE-COMPARISON-POLICY.md`](docs/RULE-COMPARISON-POLICY.md)를 참고하세요.

## 설치

1. SillyTavern을 실행합니다.
2. **확장 → 확장 설치**를 엽니다.
3. 다음 저장소 주소를 입력합니다.

   ```text
   https://github.com/p16481012/SillyTavern-DevTools
   ```

4. SillyTavern을 새로고침합니다.
5. Magic Wand 메뉴에서 **ST DevTools**를 선택합니다.

SillyTavern `1.13.5` 이상이 필요합니다.

## 읽기 전용 원칙

ST DevTools는 `generate_interceptor`를 등록하지 않습니다. 이벤트 리스너는 캡처에 필요한 참조만 보관하고 즉시 반환하며, 토큰 계산과 IndexedDB 저장은 이후 실행됩니다. Playground가 추가되기 전까지 SillyTavern의 프롬프트·캐릭터 카드·설정을 변경하는 기능은 없습니다.

## 로컬 저장과 개인정보

스냅샷은 SillyTavern에 포함된 `localforage`와 IndexedDB를 사용해 스냅샷별 개별 레코드와 채팅별 경량 인덱스로 저장됩니다. 캐릭터 카드나 채팅 파일에는 추가되지 않습니다. v0.8.8까지의 채팅별 배열 저장 데이터는 해당 채팅을 처음 읽을 때 ID와 내용을 유지한 채 새 구조로 옮기며, 새 인덱스 쓰기가 끝나기 전에는 이전 데이터를 제거하지 않습니다. 영구 저장소를 사용할 수 없으면 임시 메모리로 대체하고 패널에 새로고침 시 소실 경고를 표시합니다.

스키마 v1~v6 개별 레코드는 처음 읽을 때 v7으로 변환한 뒤 해당 레코드만 한 번 다시 저장합니다. v7은 정규화된 usage와 상관관계 개인정보 경계를 추가합니다. 구버전 `stats.totalTokens`는 입력 전용 로컬 추정치로만 옮기고 출력·캐시·provider 비용은 추측하지 않습니다. 저장된 `capture.correlationId`·`request.correlationId`와 요청 상관관계 키의 원시 값은 제거하되, 과거에 ID가 있었는지는 `hadCorrelationId` boolean으로만 남깁니다. 변환 뒤 달라진 바이트 수는 경량 인덱스와 완료된 저장 요약에 함께 반영됩니다. 손상되어 변환할 수 없는 레코드는 삭제하거나 덮어쓰지 않으며, 같은 타임라인의 정상 레코드는 계속 표시합니다. 패널에는 원문이나 내부 식별자 대신 현재 불러오기 범위에서 읽지 못한 개수만 안내합니다.

같은 채팅에 저장·삭제가 겹치면 같은 인덱스의 직렬화 잠금 안에서 처리합니다. 추가·교체는 대상 스냅샷 레코드와 경량 인덱스만 갱신하고, lifecycle·usage 후속 갱신은 스냅샷 ID와 저장 partition을 바꿀 수 없는 `updateSnapshot()` 경로에서 레코드·인덱스 바이트·완료 요약을 함께 갱신합니다. 다중 삭제는 인덱스를 한 번 읽은 뒤 선택된 레코드만 제거합니다. 이는 `localforage` 또는 IndexedDB 여러 키에 걸친 트랜잭션 전체의 ACID 원자성을 보장한다는 뜻은 아닙니다. 쓰기·읽기·삭제 실패는 패널에 오류와 재시도 버튼으로 표시하며, 캡처 저장 재시도는 새 스냅샷을 만들지 않고 같은 ID를 다시 저장합니다.

상단 톱니바퀴에서 `채팅별 보관 수`, `보관 기간`, `전체 대략적 용량`과 `불러올 스냅샷 수`를 따로 지정합니다. 신규 기본값은 보관 30개·불러오기 20개이고 기간·용량 제한은 꺼져 있습니다. 정리 정책은 먼저 기간을 지난 항목, 다음으로 채팅별 개수를 넘은 항목, 마지막으로 전체 대략적 용량을 넘긴 가장 오래된 항목을 대상으로 삼습니다. 각 채팅의 최신 정상 스냅샷과 방금 저장한 스냅샷은 보호하므로 제한보다 큰 상태가 남을 수 있으며 이때 화면에 초과 상태를 알립니다. 삭제 전에는 경량 메타데이터로 영향 범위를 계산하고 사용자의 확인을 받습니다. 불러올 수만 바꾸면 저장 데이터는 삭제하지 않습니다.

저장 상태의 `ST DevTools 추정치`는 확장이 관리하는 스냅샷과 관련 로컬 데이터의 대략적 JSON 바이트입니다. `브라우저 오리진 전체` 사용량과 quota는 `navigator.storage.estimate()`가 같은 origin의 SillyTavern 및 다른 데이터를 합산해 반환한 값이므로 두 값을 직접 빼거나 확장 전용 quota로 해석하면 안 됩니다.

저장 도구의 무결성 검사는 인덱스가 가리키지만 없는 레코드, 인덱스에서 빠진 정상 레코드, 잘못된 인덱스와 구버전 중복 컨테이너를 찾습니다. 복구는 최신 미리보기 revision을 다시 확인한 뒤 인덱스와 저장 요약을 재구성하고, 내용이 동일하다고 검증된 구버전 중복 컨테이너만 제거합니다. 손상 원문과 현재 레코드와 충돌하는 구버전 컨테이너는 증거 보존을 위해 그대로 둡니다.

같은 설정 화면의 `패널 테마`에서 SillyTavern 테마 자동 감지, 항상 밝게, 항상 어둡게를 선택할 수 있습니다. 고정 테마는 SillyTavern의 현재 테마와 독립적으로 적용되고 다음 실행에도 유지됩니다.

ST DevTools에는 내장 또는 사용자 가격표가 없습니다. 비용은 provider가 공개 응답에 통화와 함께 명시해 해당 스냅샷에 저장된 경우에만 표시하며, 그 밖의 경우에는 추정하지 않고 `계산 불가`로 남깁니다.

설정을 저장할 때 테마만 바뀌었다면 타임라인을 다시 읽지 않습니다. 불러오기·보관 범위가 바뀐 경우에도 적용 버튼을 먼저 복구하고 모달을 닫은 뒤 필요한 타임라인만 비동기로 갱신합니다. v0.8.8까지의 배열형 구버전 데이터는 보관 축소 미리보기에서 전체 스키마 변환을 수행하지 않으며, 승인 후에도 실제로 남길 최신 항목만 새 구조로 옮깁니다.

v0.8.9에서 업데이트할 때 이미 스냅샷 또는 기존 불러오기 설정이 있으면 보관 상한 100개를 먼저 승계하므로 업데이트만으로 과거 데이터가 삭제되지 않습니다. 사용자가 설정에서 더 작은 보관 수를 승인한 뒤부터 새 상한을 적용합니다. 전체 진단 내보내기처럼 사용자가 명시적으로 요청한 작업은 저장된 전체 범위를 읽을 수 있습니다.

`전체 원문`·`원문 제거본`·`메타데이터만`은 새로 캡처하는 스냅샷에 적용됩니다. `원문 제거본`은 프롬프트 관련 문자열을 길이·바이트·SHA-256 placeholder로 대체하며 일반적인 개인정보 탐지나 익명화 기능이 아닙니다. `메타데이터만`은 프롬프트 구조를 제거하고 제한된 통계와 lifecycle만 남기므로 탐색·비교·검색·규칙 검사의 상당 부분을 사용할 수 없습니다. 더 비공개인 상태에서 원문을 복원하는 역변환은 지원하지 않습니다.

일반 내보내기와 `전체 원문` 백업에는 대화, 캐릭터 설정, 시스템 프롬프트 등 민감한 정보가 포함될 수 있으므로 공유하면 안 됩니다. 공유용 내보내기는 `원문 제거본`과 `메타데이터만`만 허용하고 원본에서 수집한 문자열 seed가 최종 문서에 남았는지 다시 검사해 발견하면 실패로 종료합니다. 이 검사는 알려진 원문 재등장을 막는 방어선이지 임의 개인정보가 없음을 보증하는 도구가 아니므로 파일을 직접 검토해야 합니다.

스냅샷 백업은 각 항목의 실제 개인정보 모드를 유지하는 스키마 v2 archive입니다. 기본 가져오기는 병합이며 동일 digest는 건너뜁니다. 같은 ID에 다른 내용이 있으면 `둘 다 유지` 또는 `건너뛰기`를 선택합니다. 전체 교체는 archive별 확인 문자열을 직접 입력해야 하며, 가져오기는 배타적 저장 잠금 안에서 수행한 뒤 read-back으로 결과를 확인합니다. 쓰기나 검증이 실패하면 가져오기 직전의 원시 저장 키와 값을 복원하고 다시 검증합니다. 브라우저 저장 장치 자체가 동시에 실패하는 상황까지 복구를 보장하지는 않습니다.

full backup은 redacted·metadata 스냅샷의 원문을 되살리지 않지만 원래 로컬 채팅 파티션은 무결성 검증에 포함해 같은 채팅으로 복원합니다. 안전 공유용 redacted·metadata archive에는 이 원시 파티션을 기록하지 않습니다. 가져온 결과가 현재 채팅별 보관 수를 넘더라도 시작 시 자동 삭제하지 않으며, 설정에서 삭제 미리보기와 확인을 거쳐 정리하도록 경고합니다.

Rule Inspector 정책 JSON에는 프롬프트 원문과 감사 기록이 포함되지 않습니다. 다만 프로필·그룹·이름 패턴, 수동 지정의 소스 식별자·이름과 선택한 경우 검사 결과 식별값이 포함되므로 공유 전 직접 확인해야 합니다. 가져오기는 크기·버전·필드·참조·정규식 안전성을 검증한 뒤 저장 전 초안으로만 반영합니다. 검증 실패는 현재 저장값을 변경하지 않으며, 최종 적용 실패 시에는 네 localStorage 키의 백업 복원을 시도합니다. 브라우저 저장소는 다중 키 트랜잭션이 아니므로 복원 쓰기까지 실패한 상황의 원자성은 보장하지 않습니다.

진단 보고서는 원문 대신 개수·모델·캡처 경계·토큰 통계만 포함합니다. 가져온 진단 JSON은 크기·버전·개수 일관성·개인정보 제외 플래그와 금지 필드를 확인한 뒤 요약만 표시하며, 현재 IndexedDB에는 복원하거나 병합하지 않습니다. 두 보고서 비교도 허용 목록의 집계·스냅샷 메타데이터 변화만 반환하고 내부 ID는 결과에 노출하지 않습니다. 범위 또는 보고서 버전이 다르면 비호환 경고를 표시합니다.

## 소스 연결 상태

- `문자열 일치`: 최종 프롬프트에서 원본 문자열과 해당 문자 범위를 확인
- `정규화 일치`: NFKC·대소문자·공백·zero-width 문자만 정규화한 뒤 대응 범위를 확인
- `템플릿 추정`: 지원하는 매크로 문법의 고정 문자열 앞뒤가 제한된 범위 안에서 이어지는 후보. 계산한 연결 추정치를 함께 표시
- `구조 추출`: 캡처된 payload 구조에서 재구성한 소스
- `연결 미확인`: 지원하지 않는 치환·재배열·정규식 변환 또는 현재 요청 미포함 때문에 연결하지 못한 소스

`템플릿 추정`은 확정 연결이 아니며, `연결 미확인`은 해당 소스가 실제로 전송됐다는 뜻이 아닙니다. 카드 왼쪽 색 선은 소스 종류 구분용이며 정확도나 우선순위를 뜻하지 않습니다.

v0.9.2에서 새로 캡처한 소스는 가능한 경우 JSON pointer·메시지 번호·role·원본 값 범위·최종 범위를 `구조 위치`에 표시합니다. v0.9.2 이전 스냅샷은 당시 저장하지 않은 구조 위치를 소급 추정하지 않으므로 `이전 스냅샷 · 위치 기록 없음`으로 표시됩니다.

## 멀티모달 토큰 추정

요청에 이미지 크기 또는 오디오·비디오 길이가 있으면 공식 제공자 규칙을 이용해 별도 추정치를 표시합니다.

- OpenAI: 지원 모델의 32px 패치 또는 512px 타일 방식
- Anthropic: 28px 시각 패치와 모델 세대별 해상도 상한
- Google Gemini: 768px 이미지 타일, 오디오 초당 32, 비디오 초당 263 토큰

패널은 `약`, `최소`, `최대`, `추정 불가`를 구분하고 사용한 제공자·산정 방식을 함께 표시합니다. 이 값은 캡처된 크기·길이 메타데이터로 계산한 참고치이며 provider 응답의 실제 사용량이나 청구 금액을 뜻하지 않습니다. 공식 규칙은 [OpenAI 이미지 입력](https://developers.openai.com/api/docs/guides/images-vision), [Anthropic Vision](https://platform.claude.com/docs/en/build-with-claude/vision), [Gemini 토큰 계산](https://ai.google.dev/gemini-api/docs/tokens)을 기준으로 합니다.

## 개발

Node.js 20 이상이 필요합니다.

```bash
npm run check
npm test
```

프로덕션 의존성과 빌드 단계는 없습니다.

UI 접근성을 수동 검토할 때는 `npm run sandbox`를 실행하고 출력된 로컬 주소를 엽니다.

구현 상태와 남은 경계는 [`docs/TECHNICAL-STATUS.md`](docs/TECHNICAL-STATUS.md), v0.12.4 실사용 검토 절차는 [`docs/USER-TEST-CHECKLIST.md`](docs/USER-TEST-CHECKLIST.md)를 참고하세요. 버전별 계획은 [`docs/ROADMAP.md`](docs/ROADMAP.md)에 정리했습니다.

AI 의미 검사는 개인정보 모드가 명시적으로 `전체 원문`인 현재 형식의 스냅샷만 허용합니다. 개인정보 메타데이터가 도입되기 전에 저장되어 v7로 지연 이전된 기록은 로컬에서 계속 열 수 있지만, 과거 원문 보존 상태를 추측하지 않도록 AI 전송에는 실패로 닫힙니다. 이런 기록을 검사하려면 업데이트 뒤 `전체 원문` 모드에서 새 테스트 스냅샷을 만드세요.
